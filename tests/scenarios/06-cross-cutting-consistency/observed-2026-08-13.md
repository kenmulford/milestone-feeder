# Brief: Admin list pages

Build the admin list pages. Each page shows a table of its records with the standard
columns for that entity, plus row actions (view / edit / delete).

Pages to build (one per entity):

1. Users
2. Orders
3. Products
4. Invoices
5. Shipments

In scope: the 10 list pages above.

### #K — Persist list-table filter, sort, and page-size state across navigation and refresh   [ui, risk:heavy]   [implied — review / trim / augment]
## Summary

Filter, sort, and page-size selections on an admin list table currently reset when the viewer navigates away and back or refreshes the page. This issue makes that state persist across both, so the viewer resumes the same table view. The persistence lives once in the shared `DataTable` component every admin list page reuses.

## Acceptance criteria

- [ ] Happy path: choosing a column filter, a sort, or a page size on an admin list table restores that same filter, sort, and page size after the viewer navigates away and back, and after a page refresh.
- [ ] Empty state: a list table with no persisted state yet loads with no filter applied, no sort applied, and the page size defaulting to 30.
- [ ] Error/failure state: persisted state that no longer resolves to a valid filter, sort, or page falls back to the same defaults as the empty state rather than failing to load the table.
- [ ] Edge state: persistence is scoped per list page, so restoring one entity's table state never applies to a different entity's table.
- [ ] Edge state: the row-actions column carries no sort or filter, so it has no state to persist.

## Non-goals

- Persisting filter, sort, or page-size state into exported output is out of scope; this issue covers navigation-away-and-back and page-refresh persistence only.

## Design (recorded, consistent)

- Convention followed: `project/design-system.md#Design system: data tables (standing convention)`
- Sortable + filterable columns: every column is sortable and has a column filter, EXCEPT the row-actions column (no sort, no filter on Actions). `project/design-system.md#Design system: data tables (standing convention)`
- Pagination: server-side pagination at 30 rows per page, with a page-size control defaulting to 30. `project/design-system.md#Design system: data tables (standing convention)`
- Reuse the shared `DataTable` component (`src/components/DataTable.tsx`). Do not hand-roll tables. `project/design-system.md#Design system: data tables (standing convention)`
- Filter, sort, and page-size state persists per list page across navigating away and back and a page refresh, resolved within the shared `DataTable`. `project/design-system.md#Design system: data tables (standing convention)`
- Empty state: no persisted filter, sort, or page-size selection yet; the table loads with no filter, no sort, and page size defaulting to 30.
- Loading state: the existing skeleton-row loading state covers the fetch triggered by restoring a persisted filter, sort, or page selection. `project/design-system.md#Design system: data tables (standing convention)`
- Error state: persisted state that no longer resolves to a valid filter, sort, or page falls back to the same defaults as the empty state.
- Disabled/edge state: persistence is scoped per list page, so one entity's table state is never applied to a different entity's table.
